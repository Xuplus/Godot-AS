# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Godot-AS makes AngelScript a Godot 4 scripting language, in the style of UnrealEngine-Angelscript (UE-AS). It ships as a GDExtension (no engine fork): `.as` files attach to nodes and call the typed Godot API. Phase history and measured results are in `docs/phase0.md` through `docs/phase6.md` (there's no phase 5: VS Code integration was dropped). Read the latest one before changing the runtime; it records decisions and why.

## Commands

Windows + MSVC 2022. SCons is installed as a Python module, so invoke it with `python -m SCons`. On this machine the Godot binary is `F:/Godot/Godot.exe` (4.8 dev).

```bash
python -m SCons -j16 target=editor          # build demo/bin/libgodot_as.windows.editor.x86_64.dll
godot --headless --path demo --import       # once after adding assets/scripts, registers the extension
godot --headless --path demo res://tests/run_tests.tscn   # smoke + API tests (exit code 0 = pass)
godot --headless --path demo res://tests/dodge_test.tscn  # plays the Dodge the Creeps port
godot --headless --path demo res://tests/hot_reload_test.tscn            # hot reload in a running game
godot --headless --editor --path demo res://tests/tool_test.tscn         # [tool] scripts + placeholders in the editor
godot --headless --editor --path demo res://tests/editor_test.tscn       # completion, error markers, global classes, templates, docs
godot --headless --path demo res://tests/debugger_test.tscn               # breakpoints/stepping over Godot's remote debugger protocol
godot --headless --path demo res://bench/run_bench.tscn   # benchmarks vs typed GDScript (one run)
python tools/bench.py --compare docs/bench/windows-editor.json   # best of 3, against the pre-AOT baseline (docs/benchmarks.md)
godot --headless --editor --path demo --quit-after 300    # check the editor opens without errors
python -m SCons -j16 target=template_release                            # (and template_debug) Windows libraries for exports
python -m SCons -j16 platform=web threads=no target=template_release    # needs emsdk 4.0.11 on PATH (EMSDK, EM_CONFIG)
python -m SCons -j16 platform=android arch=arm64 target=template_release  # also arch=x86_64; needs ANDROID_HOME, NDK 28.1
GODOT=F:/Godot/Godot.exe python tools/export_demo.py --scene res://tests/dodge_test.tscn --run "Windows Desktop"
```

- **Always pass the test scene explicitly.** The demo's main scene is the user's `playground_3d.tscn`, which never quits; don't change it.
- **Use `--log-file <path>` and read the file.** Godot's stdout is buffered, so a killed or timed-out run loses its prints. `--verbose` adds registration and build timings ("AngelScript: registered … / built …").
- **Benchmark baselines** are in `docs/bench/*.json` (Windows editor and release, Web), taken before AOT. Don't time `_process` with whole frames (headless Godot paces frames at 6.9 ms) or `Performance.TIME_PROCESS` (a once-per-second maximum); `run_bench.gd` times the process step between a first and a last node.
- **Running a single test:** each runner is a scene. API checks are `check(...)` calls in `demo/tests/api_test.as`, and dialect checks in `demo/tests/dialect_test.as` (coroutine checks are driven step by step from `run_tests.gd`). For a one-off experiment, add a scene or a `--script` SceneTree script under `demo/` and delete it afterwards.
- **Editor test drivers run only when their scene is on the command line** (`OS.get_cmdline_args()`): the editor reopens scenes from its saved layout, including in the user's editor, and a driver quits the editor when done.
- **A headless editor is in "command-line mode"**: Godot doesn't build script help pages there, so docs are tested through `AngelScriptLanguage.get_documentation`. The static `complete_code` / `lookup_code` / `get_templates` / `fill_template` serve tests and tools.
- **Hot-reload tests write scripts to `res://tests/hot/`** and delete them at the end. If a run is killed, delete that folder, or its classes join every later build.
- **The extension isn't hot-reloadable** (`reloadable = false`). If the user's editor is open, it holds a copy of the DLL (`~libgodot_as…dll`): the build still succeeds, but a second headless editor can't load it, and the user must restart the editor to see changes.
- **Exported games ignore a scene on the command line** (official templates). `tools/export_demo.py` copies demo/ to `build/stage/` with another main scene and exports from there (`build/<platform>/`, gitignored). Web results are in the browser console; Android results in `adb logcat -s godot` (launch `org.godotas.demo/com.godot.game.GodotAppLauncher`; use `--compatibility` on the emulator, whose software Vulkan crashes on Godot's mobile renderer). On this machine emsdk and the downloaded templates live in `D:/Projects/Godot/_downloads/`.
- **Binding tables are generated by SCons** from `thirdparty/godot-cpp/gdextension/extension_api-4-5.json` into `src/gen/api_data.gen.cpp` (gitignored). Manual run: `python tools/generate_bindings.py <api.json> <out.cpp>`.

## Architecture

### Binding generation (`tools/generate_bindings.py` → `src/bindings/api_data.h` tables)

The generator emits **data, not code**: one row per engine method, builtin method, operator, constructor, enum and constant. Each row has an AngelScript declaration string and per-argument `Kind`s. `src/bindings/runtime.cpp` registers every row with a small set of generic thunks (`asCALL_GENERIC` everywhere, for portability including the web) that decode arguments and ptrcall through a cached MethodBind / builtin / utility pointer.

The ptrcall encoding rules (mirroring godot-cpp) are easy to get wrong:
- ints travel as int64, floats as double, bools as a uint8.
- Object arguments are a pointer to the object pointer; a null object is a null *argument* pointer.
- RefCounted returns arrive with +1 reference (`K_REFOBJECT`), which `call_with_return` drops after taking its own.

Registration details that span files:
- **Namespaces:** singletons get *only* namespace functions (`Input::is_action_pressed`); methods on the type would be ambiguous. Static methods, enums and constants also live in a namespace named after the class (`Node::PROCESS_MODE_ALWAYS`).
- **Properties** become `get_x`/`set_x … property` accessors (`MF_PROPERTY`). The generator synthesizes accessors when Godot's getter has another name.
- **Signals** become `Signal get_<sig>() const property`, unless the name collides with a method or property anywhere in the class chain.
- **Vararg methods** get two declarations, with and without a trailing `const ?&in ...` (AngelScript rejects zero variadic args).
- **`Object.free()`** isn't in the API JSON and is bound by hand. So are `PI`/`TAU`/`INF`/`NAN`, string-literal `String`, Variant conversions, container `opIndex`, `foreach` operators, `await` and `__method_ref`.
- **Inheritance:** each class registers only its own methods; `RegisterObjectBaseType` (an AngelScript patch) copies the base's methods, bases first (`register_inheritance`). About 13.5k registrations, 0.33 s at startup. Singletons get no base.
- **Implicit handles:** engine classes are registered `asOBJ_IMPLICIT_HANDLE`, so `RegisterObjectType` returns the *handle* type id. The type registry is keyed on the bare id (`& ~asTYPEID_OBJHANDLE`); keep that in mind wherever a type id is compared. CScriptBuilder metadata is also keyed on the handle id for these classes (`metadata_type_id` in `as_project.cpp`).
- **`TypedArray<T>`** (`typed_array.cpp`) is a template value type with the memory of a Godot Array; the generator maps `typedarray::X` to it. It's registered before anything declares an instance, because template instances copy the methods registered so far.

### Objects (`src/bindings/proxy.*`)

Every engine class is an AngelScript ref type whose handles point at an `ASObjectProxy`. That is an instance binding with our own token, one per object.
- When the engine frees an object, its proxy outlives it but is empty: calls raise "Object was freed".
- RefCounted objects: strong script references hold one engine reference. Freshly constructed ones use `init_ref`.
- The `__self` handle of a script object is a *weak* ref (`add_self_ref`), because the engine object owns the script instance and a strong ref would be a cycle.

### Script classes extending engine classes (AngelScript patch + `NativeBaseHandler` in `runtime.cpp`)

The "native base classes" patch lets `class X : Node2D` inherit the registered type directly.
- The class gets a hidden protected `__self` handle of the native type, always property 0. The compiler reaches members the class doesn't declare through it, and converts script objects to whatever `__self` converts to (engine ancestors, `Variant`).
- `NativeBaseHandler::OnScriptObjectCreated` binds `__self` before the script constructor runs. The owner comes from a thread-local "pending owner" (`asrt::set_pending_owner`, set by `AngelScriptInstance::create`), or, for `Player()` in a script, from `AngelScriptInstance::construct_owner`, which creates the engine object and attaches the script; the new instance then *adopts* the script object being constructed.
- `HasVirtualMethod` lets `override` validate against engine virtuals. Those virtuals aren't registered as methods.
- Then `default` statements run (`apply_defaults`), from type user data `DEFAULTS_USER_DATA`.

### Dialect source pass (`src/as_source.*`)

Before compiling, each file is scanned (comments and strings skipped) for class declarations, and two forms are rewritten in place, keeping line numbers:
- `signal hit(int damage);` → `[signal] Signal hit;`. The arguments are kept in `SourceInfo` and reported by `_get_script_signal_list`.
- `default x = expr;` in a class body → `void __default_<Class>_<line>() { x = expr; }`. `make_class` collects these, base classes first.

### Method references and coroutines

- **Method references** (AngelScript patch): a method name where a `Callable` is expected compiles to `__method_ref(object, "name")`, which builds `Callable(object, name)`.
- **`await(signal)`** (`as_instance.cpp`): connects a one-shot `ASAwait` (a `CallableCustom`) and suspends the context. `run_context` hands the context, and the call's by-reference argument temporaries (heap-allocated whenever a function has reference parameters), to that awaiter. The awaiter resumes it, or aborts it if it's destroyed unfired. Suspending suspends the whole script call stack, unlike GDScript (see `docs/phase2.md`).

### Project module and script lifecycle (`src/as_project.*`, `as_script.*`, `as_instance.*`, `as_language.*`)

All `.as` files under `res://` compile into one module, like UE-AS. Classes see each other across files, and class names must be unique project-wide.
- **Builds:** `_reload` on a changed file rebuilds everything. If the build fails, files with errors are left out and the rest is rebuilt.
- **Classes:** `ASCompiledClass` holds the module via `shared_ptr`. Instances keep the version they were created from, so rebuilding never breaks live instances; this is groundwork for hot reload. `AngelScript::get_compiled()` refreshes by project generation.
- **Main class of a file:** the one named after the file, otherwise the first class extending an engine class.
- **Metadata:** `[export]` and `[signal]` are CScriptBuilder metadata. Export defaults come from compiling the field's initializer expression; constructors are never run for defaults. `[signal] Signal x;` fields are filled with the owner's signal at instance creation.
- **Calls from Godot:** `AngelScriptInstance::call` uses a per-thread context pool. Contexts are deliberately not `Unprepare`d, to keep AngelScript's fast path; this is safe because instance teardown releases `__self` first. A context suspended by `await` leaves the pool until it finishes.
- **Variant conversion** is centralized in `asrt::to_variant` / `from_variant`, keyed on AngelScript type ids via a type registry.

### Hot reload (`as_language.cpp`, `as_project.cpp`, `as_instance.cpp`)

On in editor builds only (`OS::has_feature("editor")`, so also games run from the editor).
- A watcher thread snapshots `.as` stamps with `std::filesystem` every 250 ms (`ASProject::snapshot`, no Godot API) and sets `disk_changed`. `_frame()` then runs `reload_from_disk()` on the main thread: `poll_disk()` re-reads changed files, then `build()`, then `project_rebuilt()`. Godot's `_reload_scripts` requests take the same path.
- `publish()` keeps the previous `ASCompiledClass` for files that failed to compile.
- `reload_instances()` moves each live instance whose class changed:
  1. `create_reloaded`: `CreateUninitializedScriptObject`, so no constructor and no `default` statements run.
  2. Every instance switches to its new object.
  3. `transfer_state`: fields copy by name through Variant, and fields the new version added get `evaluate_initializer`.
  4. `retire`: pending awaits on the old object are cancelled and `__self` is cut.
  Instances whose engine object no longer fits the class's native base are skipped.

### Editor services (`as_outline.*`, `as_completion.*`, `as_language.cpp`, `as_script.cpp`)

- **Outline** (`as_outline.*`): a tolerant token-level parser of a file's text. It gives classes and their members with lines, doc comments and metadata, plus the locals in scope at an offset. Everything that reads the text being edited uses it: global classes, completion, lookup, the member list (`_validate`'s functions) and docs. So these keep working while the file doesn't compile.
- **Global classes:** every file's main class. `_get_global_class_name` is called from the editor's scan threads, so it reads the file from disk and outlines it (`ASProject::summarize`), never compiling. `AngelScript::_get_global_name` must give the same name.
- **Completion and lookup** (`as_completion.*`) resolve the expression chain before the cursor. Classes of the edited file come from the outline; the API and other files come from the engine and `ASProject::get_latest_module()`. Engine messages are silenced while they query types.
- **Debugger:** only when `EngineDebugger::is_active()` at `_init` (a game run from the editor).
  - `acquire_context` gives each context a line callback and an exception callback.
  - `run()` keeps a per-thread stack of running contexts (`running`), which the `_debug_*` stack functions read.
  - The line callback mirrors GDScript's `OPCODE_LINE`. Step depth comes from changes in the total call-stack size.
  - Debugger answers (step counter, breakpoints) are cached per thread and refreshed every 64 lines, at calls and returns, and after a break.
  - Per-thread state must be plain data. A thread_local with a constructor is guarded on every access by MSVC, and one holding a `StringName` crashed the DLL at load.
  - Don't call `GetUserData` on hot paths: it takes an engine lock.

### Shipping (`ASProject::make_package` / `load_package`, `src/editor/as_export_plugin.*`)

- On export, `AngelScriptExportPlugin` compiles the project into `res://angelscript.asbin` (a Variant dictionary): bytecode plus what make_class needs without sources, which is file class/signal declarations, `ASMetadata` ([export]/[signal]/[tool]) and export defaults. Each `.as` file is replaced by `STUB_SOURCE`, because scenes reference scripts by path.
- A game without the `editor` feature that finds the package runs in `package_mode`: `ensure_scanned` loads it, `build` loads the bytecode, and `set_source` is a no-op (the loaded .as files are stubs).
- Anything make_class needs must come through `ASMetadata` or the package's `File` data, never CScriptBuilder or source text.
- Bytecode carries each script class's native base (an AngelScript patch in `as_restore.cpp`).
- Web and Android build AngelScript with `AS_MAX_PORTABILITY`. Registrations must stay `asCALL_GENERIC`; callbacks (message, line, exception) can be CDECL.

### Editor (`src/editor/`)

The syntax highlighter is an `EditorSyntaxHighlighter` that reports the "AngelScript" language. An `EditorPlugin` registers it at `MODULE_INITIALIZATION_LEVEL_EDITOR`, under `#ifdef TOOLS_ENABLED`. A file the editor already had open keeps its saved highlighter choice.

## Conventions

- Godot's snake_case API names are kept as-is. Scripts use the Phase 2 dialect (`Node n`, `signal x();`, method references, `await`); `demo/tests/api_test.as` deliberately keeps the older explicit `@` syntax, which must keep working.
- `thirdparty/angelscript` is vendored AngelScript 2.38.0 with local patches. Mark every change with `GODOT-AS PATCH (name)` and record it in `thirdparty/angelscript/PATCHES.md`, so patches survive upgrades.
- Patch scripts that write C++ or AngelScript through the Bash tool can turn `\n` in string literals into real newlines; check the result or use the Edit tool for such lines.
- godot-cpp targets API 4.5 (oldest supported) while running on newer Godot.
- Write phase results, with measured numbers, into `docs/phaseN.md`.
